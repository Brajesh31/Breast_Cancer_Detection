# 📑 Technical Reports and Review Records

Store durable, non-sensitive project reports here. Examples include dataset audits, reproducibility reviews, notebook quality reviews, dependency reviews, and experiment summaries.

## Report requirements

Every report should state its date, author or reviewer, commit SHA, scope, commands executed, observed evidence, limitations, and follow-up actions. Distinguish checks that passed from checks that were not run.

Use [the test report template](../templates/test-report-template.md) for verification records and [the risk assessment template](../templates/risk-assessment-template.md) for risk reviews.

## Data safety

Never commit patient records, personal health information, private credentials, or confidential third-party material. Use synthetic examples when demonstrating report formats.
